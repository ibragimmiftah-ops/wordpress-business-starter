# Чек-лист передачи WordPress-сайта клиенту

Используй этот файл для каждого проекта. Передача считается завершённой только после критических пунктов.

## 1. Владение и доступы

- [ ] Домен оформлен на клиента или клиент явно подтвердил схему владения.
- [ ] Клиент имеет доступ к регистратору домена и DNS.
- [ ] Хостинг оформлен на клиента либо передан полный доступ владельца.
- [ ] У клиента есть собственный WordPress Administrator account.
- [ ] Удалены временные/тестовые admin-пользователи, которые больше не нужны.
- [ ] Для разработчика оставлен отдельный аккаунт, если заключена поддержка.
- [ ] Пароли не передаются открытым текстом в README/Git.
- [ ] Репозиторий передан клиенту или клиент добавлен владельцем/администратором по договорённости.
- [ ] Все платные лицензии понятно закреплены: кто владелец, кто продлевает, дата продления.

## 2. Домен, DNS и HTTPS

- [ ] Основной домен открывает production-сайт.
- [ ] `www` либо работает, либо корректно редиректит на основной домен.
- [ ] DNS-записи документированы.
- [ ] HTTPS работает без предупреждений браузера.
- [ ] HTTP делает 301/308 redirect на HTTPS.
- [ ] Сертификат автоматически продлевается.
- [ ] Нет mixed-content ошибок HTTP/HTTPS.

## 3. WordPress

- [ ] WordPress обновлён до поддерживаемой стабильной версии.
- [ ] Тема и плагины обновлены.
- [ ] Неиспользуемые темы удалены, кроме разумной резервной стандартной темы при необходимости.
- [ ] Неиспользуемые плагины удалены.
- [ ] Нет двух SEO/cache/security-плагинов с одинаковыми задачами.
- [ ] Permalinks настроены на человекочитаемую структуру, например `/%postname%/`.
- [ ] Site Title, Tagline, timezone, language и admin email проверены.
- [ ] Регистрация пользователей выключена, если бизнесу она не нужна.
- [ ] Комментарии выключены, если они не используются.
- [ ] Debug выключен на production (`WP_DEBUG=false`).

## 4. Контент и дизайн

- [ ] Нет lorem ipsum, тестовых текстов и placeholder-изображений.
- [ ] Логотип и favicon корректные.
- [ ] Телефон, email, адрес и мессенджеры клиента проверены.
- [ ] Все CTA ведут туда, куда должны.
- [ ] Все ссылки проверены.
- [ ] Нет пустых страниц/секций.
- [ ] Изображения имеют разумный размер и современный формат где возможно.
- [ ] У значимых изображений есть `alt`.
- [ ] Mobile 320–430 px проверен.
- [ ] Tablet проверен.
- [ ] Desktop проверен.
- [ ] Chrome/Safari/Firefox проверены хотя бы на критических страницах.

## 5. Формы и заявки — критично

- [ ] Каждая форма реально отправлена тестово с production-домена.
- [ ] Заявка приходит в нужный email/CRM/таблицу.
- [ ] SMTP или транзакционная email-доставка настроена и протестирована.
- [ ] SPF/DKIM/DMARC проверены у почтового домена, если используется доменная почта.
- [ ] В форме есть понятный success state.
- [ ] Есть error state.
- [ ] Валидация обязательных полей работает.
- [ ] Spam protection подключена, если сайт публичный и форма получает спам.
- [ ] Не собираются лишние персональные данные.
- [ ] Клиент понимает, где смотреть сохранённые Leads/заявки.

## 6. SEO и индексация

- [ ] У каждой важной страницы уникальный `<title>`.
- [ ] Meta description заполнены для ключевых страниц.
- [ ] На странице один основной H1.
- [ ] Иерархия H2/H3 логична.
- [ ] Canonical корректен.
- [ ] XML sitemap существует и открывается.
- [ ] `robots.txt` не блокирует production по ошибке.
- [ ] В WordPress выключено `Discourage search engines from indexing this site` на production.
- [ ] Google Search Console подключён к аккаунту клиента.
- [ ] Sitemap отправлен в Search Console.
- [ ] 404-страница работает.
- [ ] Старые URL получили 301 redirect, если сайт заменяет существующий.

## 7. Аналитика

- [ ] Аналитика принадлежит клиенту.
- [ ] Production-трафик поступает в правильный property/container.
- [ ] Основные конверсии настроены: submit form / call / WhatsApp / booking по задаче.
- [ ] Внутренний/тестовый трафик учтён или отфильтрован по необходимости.
- [ ] Cookie consent настроен, если этого требует используемая аналитика/юрисдикция.

## 8. Безопасность

- [ ] Уникальный сильный пароль администратора.
- [ ] 2FA включена хотя бы для администраторов, если поддерживается выбранным стеком.
- [ ] Минимальное количество admin-пользователей.
- [ ] Никаких API keys/passwords в Git.
- [ ] File editor WordPress отключён на production по возможности (`DISALLOW_FILE_EDIT`).
- [ ] Автоматические обновления настроены осознанно.
- [ ] Security plugin/WAF выбран по реальным требованиям, а не установлен «для галочки».

## 9. Backup и восстановление — критично

- [ ] Автоматический backup базы данных настроен.
- [ ] Автоматический backup файлов/uploads настроен.
- [ ] Копии хранятся не только на том же сервере, если проект критичный.
- [ ] Определён срок хранения backup.
- [ ] Сделан свежий backup перед передачей.
- [ ] Выполнен хотя бы один тест восстановления на staging/local для важных проектов.
- [ ] Клиент знает, кто отвечает за восстановление после передачи.

## 10. Производительность

- [ ] Главная страница проверена Lighthouse/PageSpeed как диагностика.
- [ ] Нет огромных исходных изображений по 5–20 MB.
- [ ] Lazy loading используется там, где уместно.
- [ ] Cache настроен на уровне хостинга/CDN/плагина без конфликтов.
- [ ] Неиспользуемые тяжелые плагины удалены.
- [ ] Core Web Vitals проверены хотя бы на ключевых шаблонах.

## 11. Юридические страницы

- [ ] Privacy Policy заполнена данными реального бизнеса.
- [ ] Cookie Policy/consent есть, если требуется.
- [ ] Terms/Imprint/Legal Notice добавлены, если требует бизнес или юрисдикция.
- [ ] В формах есть необходимое уведомление/согласие на обработку данных.
- [ ] Юридические тексты подтверждены клиентом; разработчик не выдаёт шаблон за юридическую консультацию.

## 12. Финальная передача

- [ ] Клиент получил URL сайта.
- [ ] Клиент получил `/wp-admin` URL.
- [ ] Клиент получил доступ к домену/DNS.
- [ ] Клиент получил доступ к хостингу.
- [ ] Клиент получил доступ к GitHub/исходникам по договорённости.
- [ ] Клиент получил Analytics/Search Console.
- [ ] Клиент получил email/SMTP/формы/CRM доступы, если они входят в проект.
- [ ] Передан список платных сервисов и регулярных платежей.
- [ ] Передана инструкция «как поменять текст/фото/услугу/контакт».
- [ ] Зафиксирована дата окончания бесплатных правок/гарантийного периода, если он есть.
- [ ] Зафиксировано, кто отвечает за updates, backups, security и content после передачи.
- [ ] Финальная копия/backup создана после утверждения production.
